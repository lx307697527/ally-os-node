# Dev harness — ported from ally-os

The agent development process that built ally-os was ported here on 2026-10-01 so
migration work in this repo runs under the same discipline. This file records what
came over, what deliberately did not, and how ally-os concepts map onto this repo.
Original locations: `ally-os/.claude/`, `ally-os/scripts/`, `ally-os/ops/`,
`ally-os/harness.toml`.

## What was NOT ported, and why

- **The Supabase guard suite** (`guards/` + ~40 `check_*.py` in `scripts/`): they
  enforce RLS/pgTAP/migration-naming/module-map invariants of a stack this repo
  does not have. This repo's equivalents: `pnpm verify` (lint → typecheck → test),
  the schema/migration CI check, and code review.
- **`post-commit` signature advisory + `check_commit_signatures.py`**: commit
  signing is not configured in this repo yet. Revisit when it is.
- **Code-intelligence layer** (serena/codegraph, `fact_layer_ready_hook.py`,
  `report_blast_radius.py`, CODE-INTELLIGENCE docs): optional accelerator; the
  hooks degrade gracefully without it, so it was simply not wired.
- **Backlog system** (`ops/backlog/backlog.yaml`, backlog-close/reconcile GitHub
  Actions, `validate_backlog.py`): GitHub issues are the tracker here.
- **Guard self-test suite** (`scripts/tests/`, pytest): not ported with the
  scripts. If a ported script is modified, smoke-test it by hand until the suite
  is brought over.

## Concept mapping (ally-os → ally-os-node)

| ally-os skill/reference | Read here as |
|---|---|
| `ops/backlog/backlog.yaml`, backlog phase states | GitHub issue + its state; "phase done" = PR merged with `Closes #n` |
| spec file / spec ID (`FEAT-xxx`) | The issue number (`#nnn`); specs may go in `ops/specs/` when a task outgrows an issue body |
| module maps `src/modules/<mod>/CLAUDE.md` | `docs/architecture/overview.md` + package READMEs |
| migration with spec-ID header | Drizzle migration generated by `pnpm db:generate` from `packages/db/src/schema.ts` |
| test-amendment label + guard | Not present; the reviewer agent covers the intent (never weaken a test to pass) |
| `pnpm verify` equivalents (lint+unit+guards) | `pnpm verify` (lint → typecheck → test) |
| develop/release/main branch flow | `main` only (trunk-based); `branch_flow.py` behaves as OFF |

## Day-to-day use

- **Worktrees**: one linked checkout per task under `.claude/worktrees/`
  (gitignored). `git worktree add .claude/worktrees/<name> -b <branch> origin/main`.
  The SessionStart hooks repair `core.hooksPath` inside worktrees — relative, so
  each worktree runs its own revision of the hooks.
- **Claiming an issue**: `python scripts/claim_issue.py claim <N>` before starting
  work; `... release <N>` when done. The lease is a pushed git ref
  (`refs/heads/claims/issue-<N>`) — atomic, no two sessions can hold one issue.
- **Session logs**: written automatically on session end to `ops/session-logs/`;
  SessionStart reports unwritten judgments and untracked logs.
- **Pre-push**: `pnpm verify` must be green before any push. CI runs the same
  gate again.
