# Ally OS (Node) — agent instructions

Tool-agnostic instructions for AI agents (Claude Code reads this via `CLAUDE.md`).
Human-oriented overview: `README.md`. Architecture & roadmap: `docs/architecture/overview.md`.

## Commands

```bash
pnpm verify                          # lint → typecheck → test. MUST pass before claiming done.
DATABASE_URL=postgres://ally:ally@localhost:5432/ally pnpm test   # include DB integration tests
pnpm vitest run path/to/file.test.ts # single test file
pnpm db:generate                     # after editing packages/db/src/schema.ts — commit the output
```

## Code rules

- **TypeScript is fully strict** (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`).
  Do not loosen `tsconfig.base.json` or add `eslint-disable` / `@ts-expect-error` / `as any` to get green.
  Fix the type instead. If a suppression is truly unavoidable, add a comment explaining why.
- **`erasableSyntaxOnly`** — Node runs `.ts` directly by stripping types, so no `enum`, `namespace`,
  or constructor parameter properties. Use `as const` objects / union types instead.
- **Relative imports include the `.ts` extension** (`import { x } from "./x.ts"`).
- **Workspace packages export `.ts` source** (`"exports": { ".": "./src/index.ts" }`), no build step.
- **Env vars go through `@ally/config`** (`parseEnv`). Don't read `process.env` elsewhere in app code;
  add the variable to `envSchema` and `.env.example` instead.
- **Validate every external input with zod** (request bodies, webhooks, third-party API responses).
- **Dependencies are injected** (see `apps/api/src/app.ts` `AppDeps`) so routes are testable
  without a real database. Keep `index.ts` files as thin bootstrap only.
- **No cloud-vendor lock-in in app code**: storage via `@ally/storage` (S3 protocol), queues/cron via
  pg-boss, config via env vars. Vendor-specific code belongs in `infra/` only.
- **Logs go through pino** (`logger.info({ ...context }, "message")`); `console.log` is a lint error.
- **Never return internal error details to clients** — log them, return a generic error + requestId.

## Database

- Schema lives in `packages/db/src/schema.ts`; migrations in `packages/db/migrations/` are generated by
  `pnpm db:generate` — never hand-edit a migration that has already been merged.
- CI fails if `schema.ts` changes without a matching migration.
- Deploy runs migrations as a one-off ECS task **before** rolling out new code, so every migration
  must be backward-compatible with the currently running version (expand → migrate → contract).

## Tests

- Unit tests sit next to code as `*.test.ts`.
- DB integration tests use `describe.skipIf(!process.env.DATABASE_URL)`; CI provides Postgres.
- Every new route: at least one test via `app.request()`. Every bug fix: a regression test.

## Git

- Branch from `main`, PR → `main`, squash merge. Conventional commits in English: `type(scope): summary`.
- Merging to `main` auto-deploys staging; production needs manual approval in GitHub Actions.

## Dev harness (ported from ally-os)

The workflow discipline from the old repo lives here too — see
`docs/guides/dev-harness-port.md` for the full port manifest and concept mapping.
Short version:

- **Skills & agents**: `.claude/skills/` (task-intake, feature-dev, orchestrator,
  bug-fix, commit, …) and `.claude/agents/` define the intake → spec → test-first
  build → review → docs-sync → PR loop. Where they mention the ally-os backlog or
  spec IDs, read "GitHub issue" and "issue number" respectively.
- **One task, one worktree**: linked checkouts under `.claude/worktrees/`
  (gitignored), branched fresh from `origin/main`.
- **Claim before you work**: `python scripts/claim_issue.py claim <N>` takes an
  atomic lease (a pushed git ref) on issue #N so two sessions never build the same
  thing; release it when the PR lands.
- **Session logs**: `ops/session-logs/` accumulates what each session actually
  did; keep them committed.
- **Pre-push gate**: `git push` runs `pnpm verify` (installed via `postinstall` /
  `core.hooksPath scripts/hooks`). Red code does not leave the machine.
- **Rules**: `ops/rules/` — fail closed, hermetic fixtures, producers prove their
  output, English user-visible text.
